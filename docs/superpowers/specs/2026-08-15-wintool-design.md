# Спецификация: Wintool — генератор autounattend.xml

**Дата:** 2026-08-15  
**Бренд / проект:** **Wintool** («инструмент Windows»)  
**Папка репозитория:** `wintool`  
**Стек:** Next.js (App Router), React, TypeScript  
**Статус:** на проверке у пользователя  
**Заменяет:** прежнюю спеку «только файлы на флешку» (`2026-08-15-win11-autounattend-design.md`)

## 1. Цель

Сделать сайт **Wintool** — генератор `autounattend.xml` для Windows 10/11:

- удобный пошаговый UI (не простыня как у Schneegans);
- визуально в семье соседних проектов (`mikat-web`, `lokach`, `islam-answers`);
- на выходе — скачиваемый `autounattend.xml` (+ при необходимости встроенные скрипты очистки в самом XML);
- покрыть согласованный домашний сценарий и расширяемый набор опций MVP.

Сайт для себя / локального использования в первую очередь; публичный «полный клон Schneegans» — вне MVP.

## 2. Референсы UI (обязательно соблюдать)

Стиль брать с соседних Next-проектов, не с schneegans.de.

| Элемент | Как у соседей |
|---------|----------------|
| Шрифты | **IBM Plex Sans** (UI) + **Literata** (заголовки/display), кириллица |
| Иконки | **lucide-react** |
| Тема | `data-theme="light\|dark"`, по умолчанию **dark**, переключатель + favicon light/dark |
| Токены | `--bg`, `--wash`, `--surface`, `--ink`, `--muted`, `--line`, `--accent`, `--on-accent` |
| Фон | `radial-gradient` wash + `--bg` |
| Оболочка | `app-shell`, sticky **Header**, `OverlayScrollbar` (нативный скроллбар скрыт) |
| Анимации | CSS `@keyframes` / `transition` как в `lokach`/`mikat-web` (`in`, появление блоков, hover); уважать `prefers-reduced-motion` |
| Типографика | ~17px body, line-height ~1.55, `--gutter`, ограниченная ширина контента |
| Язык UI | русский (как mikat); опционально позже EN как у lokach |

**Акцент этого проекта:** свой, не копировать чужой бренд (не фиолетовый mikat и не оранжевый lokach). Рекомендация: спокойный **teal/cyan** (например light `#0f766e` / dark `#2dd4bf`) — «тех/утилита», без AI-клише purple-gradient.

Структура layout как у lokach: Header (бренд, тема) + `main` с мастером.

## 3. Продуктовый MVP — что умеет генератор

Пошаговые **блоки на одной странице** (якоря слева). Каждый блок — секция с заголовком.

### Шаг 1. Язык и регион

- Язык образа / UI: **ru-RU** (по умолчанию), опционально en-US  
- Раскладки: RU + EN (порядок настраиваемый)  
- Регион: Россия  
- Часовой пояс: **Russian Standard Time** (Москва) или «как по языку»

### Шаг 2. Редакция и ключ

- Редакция: **Pro** (дефолт), Home, Enterprise (минимум Pro + Home)  
- Ключ: нет / generic (установка без активации) / свой ключ (поле, хранить только в скачанном XML, не на сервере)

### Шаг 3. Диск

- Режим:  
  - **A.** Интерактивно (Setup спросит раздел)  
  - **B.** Стереть Диск 0 и разметить автоматически  
- В режиме B:  
  - C: размер в ГБ (дефолт **150**), метка **System**  
  - D: остаток, метка **Program**  
  - EFI + MSR + Recovery по безопасным дефолтам (UEFI/GPT)  
- Крупное предупреждение: «Диск 0 будет стёрт»  
- Опционально (nice-to-have MVP+): проверка размера диска (min/max GiB) — как идея Schneegans

### Шаг 4. Компьютер и пользователь

- Имя ПК (дефолт пустой или пример `X1505ZA`)  
- Локальный пользователь: имя (дефолт `Admin`), пароль (можно пустой)  
- Автологин при первом входе: да (дефолт)  
- Без обязательного Microsoft-аккаунта  

### Шаг 5. Приложения (bloat)

Белый список «оставить» (чекбоксы, дефолт включены):

- Edge (всегда / не предлагать снос)  
- Калькулятор  
- Блокнот  
- Windows Terminal  
- PowerShell  
- Microsoft Store  
- Фотографии  
- Media Player / Кино и ТВ  

Остальные известные пакеты — снимать (список как у типичного Remove bloatware; точный каталог пакетов — в коде генератора).

Дополнительно простые тумблеры:

- отключить виджеты  
- не ставить Consumer Features / suggestions  
- Express settings: минимум телеметрии  

### Шаг 6. Обзор и скачивание → блок `#download`

- Сводка всех выборов  
- Кнопка **Скачать autounattend.xml**  
- Краткая инструкция: положить в корень флешки рядом с `setup.exe`  
- (Опционально) копировать XML в буфер  

## 4. Архитектура

```
Browser (Next.js UI)
    → POST /api/generate  { config }
    → TypeScript UnattendBuilder
    → application/xml  (autounattend.xml)
```

### 4.1 Почему не .NET-библиотека Schneegans в рантайме Next на Vercel

[cschneegans/unattend-generator](https://github.com/cschneegans/unattend-generator) (MIT) — отличный движок, но это **.NET**. Соседи деплоятся как обычный Next (Vercel и т.п.), где DLL неудобна.

**Решение MVP:** собственный **TypeScript XML builder** с узким контрактом настроек. Структура answer file — по документации Microsoft; при сомнениях сверяться с публичными примерами / MIT-кодом Schneegans как **референсом алгоритмов**, с указанием лицензии MIT в README/`NOTICE`.

**Позже (вне MVP):** опциональный режим «локальный генератор» через `UnattendGenerator.dll` + PowerShell 7 для полного паритета с сайтом Schneegans.

### 4.2 Стек реализации

- Next.js App Router (версия в духе соседей: 15.x / 16.x)  
- React 19 + TypeScript  
- CSS как у соседей (отдельные `.css` у компонентов **или** globals + модули — предпочтительно тот же паттерн, что `lokach`: component CSS)  
- `lucide-react`  
- Без обязательного Tailwind, если соседи без него в runtime UI (mikat имеет tailwind в package, lokach — чистый CSS). **Предпочтение: чистый CSS + переменные**, как lokach/islam-answers.  
- API Route: `app/api/generate/route.ts`  
- Валидация конфига (zod или ручные type guards)  

### 4.3 Модель конфига (логическая)

```ts
type UnattendConfig = {
  language: 'ru-RU' | 'en-US'
  keyboards: Array<'ru' | 'en'>
  timezone: string
  edition: 'Pro' | 'Home' | 'Enterprise'
  productKey: null | 'generic' | string
  disk: { mode: 'interactive' } | {
    mode: 'wipe0'
    windowsGb: number
    labelC: string
    labelD: string
  }
  computerName: string
  user: { name: string; password: string; autoLogon: boolean }
  keepApps: string[]      // whitelist ids
  tweaks: {
    disableWidgets: boolean
    disableConsumerFeatures: boolean
    expressPrivacy: 'disable-all' | 'default'
  }
}
```

## 5. Страницы и UX

| Маршрут | Содержание |
|---------|------------|
| `/` | Одна страница генератора (основной продукт) |
| `/help` | Как пользоваться флешкой, риски диска, UEFI (опционально в MVP) |
| Footer | **Нет** — не добавлять |

### 5.1 Компоновка главной

Две колонки на десктопе:

| Зона | Содержание |
|------|------------|
| **Левая** (sticky) | Блок навигации по секциям: якорные ссылки (`#language`, `#edition`, `#disk`, …). Активный пункт подсвечивается при скролле (Intersection Observer или аналог). |
| **Правая** | Все блоки формы **на одной странице** друг под другом (не отдельные экраны wizard с «Далее»). |

На узких экранах: левый блок сверху горизонтально / компактный список якорей, затем контент.

### 5.2 Якоря и блоки (порядок)

1. `#language` — язык и регион  
2. `#edition` — редакция и ключ  
3. `#disk` — диск  
4. `#account` — компьютер и пользователь  
5. `#apps` — приложения / bloat  
6. `#tweaks` — виджеты / privacy  
7. `#download` — обзор и скачивание  

Клик по пункту слева — плавный скролл к якорю (`scroll-behavior` + учёт sticky header, если есть).

### 5.3 Прочее UX

- Header сверху (бренд **Wintool**, переключатель темы); **без footer**  
- анимация появления блоков (`in` / fade), как у соседей;  
- на блоке диска — визуально сильный warning;  
- мобильная вёрстка: крупные контролы;  
- ошибки валидации рядом с полями.

## 6. Безопасность и этика

- Не логировать и не сохранять product key / пароли на сервере (stateless generate).  
- Явные предупреждения про wipe диска.  
- В README: MIT notice, если заимствованы идеи/фрагменты логики из Schneegans; ссылка на оригинал.  
- Не позиционировать как «официальный Microsoft».  

## 7. Вне скоупа MVP

- Полный паритет всех опций schneegans.de  
- Установка стороннего софта (winget/Chrome/VLC)  
- Онлайн-аккаунты, мультиарендность  
- Генерация ISO обёртки  
- Поддержка Legacy BIOS (только UEFI/GPT в режиме wipe)  
- Десктоп-приложение  

## 8. Критерии готовности

1. Сайт в стиле соседних проектов (шрифты, тема, scrollbar, анимации, lucide).  
2. Левый блок якорей + секции на одной странице; без footer.  
3. Генерация отдаёт валидный на вид XML.  
4. Дефолты: ru-RU, Pro, wipe Disk0 C150/D, Admin без пароля, whitelist приложений.  
5. `npm run build` проходит.  
6. README: как запустить локально и куда класть XML на флешку.

## 9. План после утверждения

1. Создать проект `~/Projects/wintool`, `move_agent_to_root`.  
2. Writing-plans → пошаговая реализация.  
3. Скелет Next + UI shell как у lokach.  
4. Контракт конфига + builder XML + API.  
5. Мастер по шагам.  
6. Проверка XML глазами / по возможности в VM.
